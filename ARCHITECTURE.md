# ARCHITECTURE.md — Technical Specification

Source of truth for the structure, naming, endpoints, and dependencies of this project. `CLAUDE.md` governs *process*; this file governs *what gets built*.

## 1. Overview

A decoupled full-stack application for the wtvision assignment:

- **Backend** — Django 5 + Django REST Framework serving a JSON API only (no Django templates). JWT auth via SimpleJWT. PostgreSQL for storage.
- **Frontend** — React 18 (Vite, plain JavaScript) SPA. Redux Toolkit for state. SCSS modules for styling. A custom `useApi` hook owns all HTTP traffic and token refresh.
- **Infrastructure** — Docker Compose orchestrating three services (db, backend, frontend) on one network, with a named volume for Postgres data.

The product: a user logs in, sees a list of items (generic key-value entries), and can edit them. Item objects may carry arbitrary extra fields; the UI must render whatever it receives.

## 2. Key decisions and rationale

| Decision | Choice | Why |
|---|---|---|
| React tooling | Vite | CRA is deprecated; Vite is the current default, has first-class SCSS module support and a dev proxy. |
| Language | Plain JS | TypeScript deferred to an optional post-completion conversion (see assignment Bonus). |
| HTTP client | Native `fetch` | Axios interceptors would implement the refresh logic for us; the assignment wants that logic inside a custom hook. |
| State | Redux Toolkit | Assignment bonus; modern Redux (`createSlice`, `createAsyncThunk`), far less boilerplate than legacy Redux. |
| Routing | react-router-dom v6 | Standard; needed for /login vs / and the route guard. |
| Token storage | localStorage, mirrored into Redux | Simplest correct option for a demo. Documented tradeoff: vulnerable to XSS; production alternative is httpOnly cookies. State the tradeoff in README. |
| CORS strategy | Vite dev proxy (primary) + django-cors-headers (fallback) | Proxy makes the browser see one origin in dev; cors-headers keeps the API usable if someone runs the frontend unproxied. |
| JSON seeding | Django management command | More idiomatic than an ad-hoc script; shows Django structure knowledge. |
| DB in dev | Postgres via Docker from the start | It is the bonus target anyway; avoids a mid-project SQLite→Postgres migration. |

## 4. Backend specification

### 4.1 Models (`items/models.py`)

`BaseModel` — abstract (`Meta.abstract = True`, so no table):
- `id`: UUIDField, primary key, default uuid4, not editable.
- `created_at`: DateTimeField, `auto_now_add=True`.
- `updated_at`: DateTimeField, `auto_now=True`.

`Items(BaseModel)`:
- `key`: CharField, `max_length=50`, no null, no blank.
- `value`: TextField (assignment says "string field"; TextField avoids an arbitrary length cap).

### 4.2 API (`serializers.py`, `views.py`, `urls.py`)

- `ItemsSerializer`: ModelSerializer over all fields; `id`, `created_at`, `updated_at` read-only.
- `ItemsViewSet`: ModelViewSet — the router auto-exposes list/retrieve/create/update/partial_update/destroy. Default ordering: `-created_at`.
- Router registered at `items`, mounted under `/api/` → final path `/api/items/`.
- Permissions: DRF default `IsAuthenticated` set globally in settings. The items API must 401 without a token.

### 4.3 Auth (SimpleJWT)

- `POST /auth/token/` → `{access, refresh}` (SimpleJWT `TokenObtainPairView`).
- `POST /auth/token/refresh/` → `{access}` (`TokenRefreshView`).
- Paths are exactly as above, NOT under `/api/` — the assignment specifies them literally.
- Access token lifetime: 5 minutes (temporarily set to ~30 seconds while developing/testing the refresh path in `useApi`, then restore).
- Test user created via `createsuperuser` (documented in README).

### 4.4 Settings and environment

`settings.py` reads from environment via `python-dotenv` / `os.environ`:
`SECRET_KEY`, `DEBUG`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST` (=`db` inside compose, `localhost` outside), `POSTGRES_PORT`, `CORS_ALLOWED_ORIGINS`.

All values live in the committed `.env` (Bonus-4 — intentional for this dummy project; README notes this is never done in real projects).

### 4.5 Seed command (`seed_items.py`)

`python manage.py seed_items` reads `data/items.json`, validates each entry has `key` and `value`, and creates rows. Idempotency rule: wipe-and-reload (delete all Items, then insert) so the command can be rerun safely. Extra JSON fields beyond model fields are ignored by the loader — but see §6 for why they exist.

## 5. Frontend specification

### 5.1 Routes and pages

| Route | Page | Behavior |
|---|---|---|
| `/login` | LoginPage | Username/password form → POST `/auth/token/` → store tokens → redirect to `/`. Shows inline error on 401. If already authenticated, redirect to `/`. |
| `/` | ItemsPage | Wrapped in `ProtectedRoute` (no token → redirect `/login`). Fetches `/api/items/` on mount, renders responsive grid of `ItemCard`s, edit via `EditItemModal` → PATCH. Loading + error states required. |

### 5.2 Dynamic rendering rule (critical assignment requirement)

`ItemCard` receives one item object and must:
- Render `item.key` as the title and `item.value` as the body.
- Iterate over ALL remaining fields (`Object.entries`, excluding key/value/id/created_at/updated_at or optionally showing timestamps subtly) and render them generically as label→value rows.
- Handle non-string values (numbers, booleans, arrays, nested objects) without crashing — stringify sensibly.
- Zero hard-coded field names besides `key` and `value`.

The evaluator will swap in a different JSON file; this component is what makes that work.

### 5.3 `useApi` hook (`api/useApi.js`)

Public shape: returns `{ request, get, post, patch, del }` (or equivalent), each returning a promise of parsed JSON.

Internal contract:
1. Read the access token (from Redux store / localStorage) and attach `Authorization: Bearer <token>` to every request.
2. On a 401 response: POST the refresh token to `/auth/token/refresh/`.
   - Success → persist the new access token (Redux + localStorage), retry the ORIGINAL request exactly once with the new token.
   - Failure → clear all tokens, dispatch logout, redirect to `/login`.
3. The retry happens at most once per original request — a second 401 after refresh surfaces as an error (prevents infinite loops).
4. Never attach the Authorization header to the two auth endpoints themselves.
5. Non-401 errors reject with a useful error object ({status, body}) for the slices to store.

Design note to document in README: the hook is the single owner of HTTP + auth mechanics; Redux thunks call the hook's functions; components never call fetch directly.

### 5.4 Redux (`store/`)

- `authSlice`: `{access, refresh, username, status}`. Actions: `setTokens`, `logout`. Initialized from localStorage. `logout` clears localStorage.
- `itemsSlice`: `{items: [], status: 'idle'|'loading'|'succeeded'|'failed', error}`. Async thunks: `fetchItems`, `updateItem`. Reducers handle pending/fulfilled/rejected. `updateItem.fulfilled` replaces the single edited item immutably.
- `store/index.js`: `configureStore` with both reducers.

### 5.5 Styling

- SCSS modules per component; shared tokens in `styles/_variables.scss` (imported via Vite's `additionalData` or explicit `@use`).
- `global.scss`: minimal reset, base font, background.
- Responsive grid: CSS Grid with `auto-fill/minmax` for the items list; single column under a mobile breakpoint.
- No component libraries. No CSS frameworks.

### 5.6 vite.config.js

- React plugin.
- Dev proxy: forward `/api` and `/auth` to `http://localhost:8000` (or `http://backend:8000` when the frontend dev server itself runs inside compose). All frontend code uses relative URLs (`/api/items/`) — no hard-coded backend origin.

## 6. Seed data (`data/items.json`) — self-authored

Schema: a JSON array of objects. Every object MUST have `"key"` (≤50 chars) and `"value"` (string). Several objects SHOULD carry extra fields of varied types — extra strings, numbers, booleans, an array, a nested object — because the frontend's dynamic rendering must be proven against them. Include 10-15 entries with realistic variety (config-style entries, feature flags, descriptive text). This file doubles as the project's test fixture for the "drop in a replacement JSON" requirement.

## 7. Docker

### 7.1 docker-compose.yaml — three services

- `db`: `postgres:16-alpine`. Env from `.env`. Named volume `pgdata:/var/lib/postgresql/data`. Healthcheck: `pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}` (interval ~5s).
- `backend`: build `./backend`. `depends_on: db: condition: service_healthy` (this — not bare depends_on — is what prevents the connect-before-ready crash). Bind mount `./backend:/app` for autoreload. Command in dev: `python manage.py runserver 0.0.0.0:8000`. Port 8000:8000. Env from `.env` with `POSTGRES_HOST=db`.
- `frontend`: build `./frontend`. Bind mount `./frontend:/app` plus anonymous volume for `/app/node_modules` (so the host folder does not shadow container-installed deps). Command: `npm run dev -- --host`. Port 5173:5173.

Named volumes: `pgdata`.

### 7.2 Dockerfiles

- `backend/Dockerfile`: `python:3.13-slim` → workdir /app → copy requirements → pip install → copy source. (3.13 rather than 3.12 so the image matches the local venv Python — the dev machine has no 3.12, and a `pip freeze` taken on one minor version then installed on another is avoidable drift.) Dev runs runserver via compose command; gunicorn is present for a prod-style run.
- `frontend/Dockerfile`: `node:20-alpine` → workdir /app → copy package files → npm install → copy source. Dev server via compose command. (A production multi-stage build with nginx is optional/stretch — note it in README if skipped.)

## 8. API contract summary

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | /auth/token/ | none | Login → {access, refresh} |
| POST | /auth/token/refresh/ | none (refresh in body) | New access token |
| GET | /api/items/ | Bearer | List items |
| POST | /api/items/ | Bearer | Create item |
| GET | /api/items/{id}/ | Bearer | Retrieve |
| PATCH | /api/items/{id}/ | Bearer | Partial update (UI edit uses this) |
| PUT | /api/items/{id}/ | Bearer | Full update |
| DELETE | /api/items/{id}/ | Bearer | Delete |
